SAP 自动化概述

SAP GUI 自动化的四大难点

SAP GUI 是基于 SAP 专有协议的客户端，和普通 Windows 程序不同，自动化面临四大核心挑战[1]：

难点说明
元素ID不固定SAP GUI的控件ID会根据屏幕布局变化。同样的"物料编号"输入框，不同事务码下ID不一样，今天能用的定位明天可能失效
脚本功能默认关闭SAP默认不允许第三方脚本操控GUI，未开启时RPA工具识别不到SAP界面元素
系统响应延迟SAP事务处理会有0.5-3秒延迟，查询、过账都会有等待，不加等待就会点击失败
特殊控件无法直接操作SAP的Grid View（ALV报表）、树形控件、导航栏不是标准Windows控件，普通点击无效

此外，SAP GUI 安装后默认并不允许外部脚本控制界面，很多脚本"连不上"的根因在于 SAP GUI 设置里把脚本功能关了[2]。

为什么需要 RPA

OA 和 SAP 几乎是所有企业都会使用的信息管理系统。虽然这些系统给企业信息化带来了便利，但依赖人工操作、效率提升难这一痛点仍困扰大多数企业。RPA 通过模拟人工在计算机上的操作，将规则性强、重复性高的业务实现自动化[3]。

核心价值：非侵入性部署（RPA 能把对现有系统的影响降到最小，与 OA、SAP 无缝连接，无需开发接口、不用懂 ABAP）；7×24 小时精准执行；流程标准化。有客户通过 RPA 将月度财务关账流程从 3 天缩短到 4 小时[4]。

前提准备：SAP GUI Scripting 启用

SAP GUI Scripting 的启用必须同时配置服务端和客户端，否则客户端拒绝对 UI 的访问。如果不能在服务端打开，就只能用图像识别方式[6]。

步骤一：服务端参数配置（事务码 RZ11）

  1. 启动 saplogon.exe，用账号密码登录 SAP 进入主页。
  2. 在命令框输入事务码 RZ11，按回车。
  3. 参数名称输入 sapgui/user_scripting，点击"显示"。
  4. 点击"更改值"，新值设置为 TRUE，保存更改[7]。
  5. 重复，将以下参数值改为 FALSE：
    • sapgui/user_scripting_disable_recording → FALSE
    • sapgui/user_scripting_force_notification → FALSE
    • sapgui/user_scripting_per_user → FALSE
    • sapgui/user_scripting_set_readonly → FALSE
  6. 注销后重新登录 SAP。

重要：事务 RZ11 中对参数的所有更改均立即生效，但在系统重新启动时丢失。要使更改永久生效，需联系 SAP 系统管理员。若重启 SAP Service 之后要重新设置服务端脚本设置[7][8]。

步骤二：客户端启用脚本

  1. 登录 SAP 后，点击菜单栏 "定制本地布局"（快捷键 Alt + F12），选择 "选项"[8]。
  2. 在弹出窗口点击 "辅助功能与脚本" → "脚本"。
  3. 勾选 "启用脚本(Enable Scripting)"。
  4. 取消勾选以下两项（避免运行时弹通知干扰）：
    • "在脚本附加到SAP GUI时发出通知"
    • "在脚本打开连接时发出通知"

步骤三：启用对话框模式（日期选择/帮助必用）

  1. 点击菜单 "帮助(H)" → "设置(N)"。
  2. 在"用户DDIC的人员设置"对话框，选 "F1帮助" 页签，选中 "以对话框模式"。
  3. 选 "F4帮助" 页签，在"显示"区域选中 "控制(amodal)"[8]。

补充：录制/回放时需保证产品与 SAP 客户端以同样权限执行；RDP/Citrix 环境需以管理员权限启动 SAP；配置完成后需重启 SAP 才可生效；SAP GUI 7.4+ 客户端支持自动化。

RPA 工具侧准备

  1. 打开 RPA 设计器（影刀/UiPath），新建自动化应用。
  2. 左侧指令面板搜索"SAP"，找到 "登录SAP" 核心指令[4][9]。
  3. 配置连接参数：连接名自定义（如 MySAP_PRD）；SAP窗口标题手动打开 SAP 登录窗口复制完整标题粘贴。
  4. 安装时勾选"影刀浏览器"和"图像识别组件"（图像识别兜底所需）[10]。
  5. Windows 11 需关闭"屏幕截图工具"后台权限，否则 RPA 截屏识别时会被系统拦截[10]。

元素拾取策略

影刀/UiPath 在桌面场景下的元素定位"四合一"为：UIA元素、MSAA元素、坐标、图像识别。能捕获到控件名就用元素捕获，捕获不到再切图像[10]。针对 SAP，有三种核心捕获方法：

方法一：标准桌面捕获（SAP GUI Scripting 方式）

启动 RPA 元素捕获（影刀/UiPath），悬停在 SAP 界面输入框上，大多数标准 SAP 输入框可正常捕获：

  • 类型通常是 GuiTextField 或 GuiCTextField
  • 属性里有 Name，就是输入框字段名（如 MATNR 表示物料号）

捕获到元素后，"输入文本"指令可直接用。这是首选方案，前提是已开启 SAP GUI Scripting[1]。

方法二：图像识别定位（处理特殊控件）

当标准捕获失败时，用图像识别作为备用定位，再配合"坐标偏移"：先用文字识别找到标签文字，再计算标签右侧固定偏移位置找到输入框。

方法三：SAP GUI 脚本录制（最稳定）

SAP 内置脚本录制功能，录制完成后得到 VBScript，里面有每个操作的精确控件路径，可在 RPA 流程中通过 COM 接口调用。这是最稳定的 SAP 操作方式，控件路径不受屏幕分辨率影响。[1]

拾取失败的应对

无法拾取 SAP 元素时，根因通常是 SAP GUI Scripting 未开启/权限隔离[11]：

  • 检查服务端 sapgui/user_scripting 是否为 TRUE
  • 检查客户端是否勾选"启用脚本"
  • 如果选项是灰色的，说明被 SAP 管理员禁用了，需要找 IT 开通

常用操作详解

SAP 登录自动化

RPA 操作步骤[5]：

  1. 新建流程「SAP自动化」。
  2. 添加 【打开应用程序】 指令 → 路径：SAP GUI 快捷方式。
  3. 添加 【窗口激活】 指令 → 窗口标题：SAP。
  4. 添加 【点击】 指令 → 定位值：连接按钮。
  5. 添加 【填写】 指令 → 定位值：用户名输入框 → 填入：变量 sap_username。
  6. 添加 【填写】 指令 → 定位值：密码输入框 → 填入：变量 sap_password。
  7. 添加 【点击】 指令 → 定位值：登录按钮。

另一种方式是通过 Python COM 接口直接连接（无需手动登录，已有 SAP 会话时）：

SapGuiAuto = win32com.client.GetObject("SAPGUI")
application = SapGuiAuto.GetScriptingEngine
connection = application.Children(0)
session = connection.Children(0)

来源：影刀RPA SAP系统自动化入门[1]。

执行事务码（T-Code）

可视化指令方式（影刀/UiPath）[5]：

  1. 添加 【点击】 指令 → 定位值：命令框（okcd）。
  2. 添加 【填写】 指令 → 定位值：命令框 → 填入：VA01（创建销售订单）。
  3. 添加 【键盘输入】 指令 → 按键：Enter。

Python COM 方式（最稳定）：

session.findById("wnd[0]/tbar[0]/okcd").text = "/nME21N"
session.findById("wnd[0]").sendVKey(0)  # 发送回车

用 /n 前缀表示跳转到新事务码（中断当前事务），不加 /n 则在当前事务内执行[1][12]。T-Code 的价值：SAP 界面跳转的捷径，不需点击科目，直接在搜索框输入 T-Code 按回车跳转，比图像判断+点击方便且稳定。

表格 / ALV 操作

ALV Grid 控件路径格式为 tbl表名/字段名[列索引,行索引]，逐行处理时循环行索引即可[1]：

# 表格中控件路径，[列,行]定位单元格
session.findById("wnd[0]/.../tblSAPLMEPOTC_1111/ctxtMEPO1111-MATNR[1,0]").text = material

修改 SAP 表格内容：影刀社区指出目前有"读取SAP表格"指令，但没有直接的"修改SAP表格"标准指令。解决方案是 SAP 自动化配置好后，用桌面软件自动化指令（如"设置元素值(win)"指令）来操作[13]。

实战技巧：先手工操作一遍，用 SAP 自带的脚本录制功能生成 VBScript，然后参考转换成 RPA 指令[5]。

实战案例：采购订单 ME21N 批量创建

场景：每天有 100 条采购需求，要在 SAP ME21N 事务码中批量创建采购订单[9][1]。

关键操作要点

  1. 打开事务码：session.findById("wnd[0]/tbar[0]/okcd").text = "/nME21N"，发送回车。
  2. 填写供应商：控件路径 wnd[0]/usr/subSUB0:SAPMM06E:0101/.../ctxtEKKO-LIFNR。
  3. 填写行项目：ALV 表格控件路径含 [列索引,行索引]，如 ctxtMEPO1111-MATNR[1,0] 为第1列第0行的物料号。
  4. 保存：点击 wnd[0]/tbar[0]/btn[11]（保存按钮）。
  5. 获取订单号：从状态栏 wnd[0]/sbar 提取文本，用正则匹配订单号（如"采购订单 4500001234 已保存"中提取数字）。
  6. 错误处理：try-except 捕获异常，失败原因写回 Excel。

销售订单批量创建（VA01）

销售订单创建流程类似，事务码为 VA01[5]：

  1. 执行事务码 VA01。
  2. 填写订单类型 OR（标准订单）→ 回车。
  3. 填写销售组织 1000、分销渠道 10、产品组 00 → 回车。
  4. 用【Excel读取】指令读取订单数据 → 【循环】遍历。
  5. 循环内：填写物料号、数量、单价，Tab键跳转字段，点击添加新行。
  6. 点击保存按钮 → 等待2秒 → 获取状态栏订单号 → 写入日志。

财务场景实战：CO/FI 模块 8 大案例

以下案例覆盖 SAP 财务会计（FI）与管理会计（CO）核心场景，每个案例含流程图、关键 T-Code、控件路径与踩坑提示。所有案例需使用支持桌面元素操作的 RPA（影刀/UiPath），蓝印RPA不适用。

案例1：凭证批量录入与过账（FI-GL）

场景：月末需将数百条手工凭证批量录入 SAP 并过账。人工逐条 FB01/FB50 录入耗时数天，且极易借贷不平。

关键 T-Code 与控件

  • FB01：过账凭证（输入日期/类型/公司代码/行项目科目/成本中心/借贷金额）
  • FB50：总账凭证（简化输入界面）
  • 状态栏 wnd[0]/sbar：抓取凭证号
  • 借贷平衡检查：借方合计 = 贷方合计，否则保存报错

⚠️ 借贷不平无法保存：SAP 要求借贷必须平衡，RPA 需在保存前预校验 Excel 借贷合计[14]。

⚠️ 成本中心/利润中心需有效：填入无效的成本中心会弹错误对话框，需提前用 KS03 验证。

⚠️ 过账期间未开：OB52 财务账期未开则报错"账期未打开"，需财务管理员先开账期。

案例2：应收/应付对账自动化（FI-AP/AR）

场景：每月需将 SAP 应收/应付明细与银行流水或业务系统对账，人工核对 FBL1N/FBL5N 报表耗时巨大。

关键 T-Code 与控件

  • FBL1N：供应商行项目报表（应付）
  • FBL5N：客户行项目报表（应收）
  • F-44：清账（将匹配的凭证标记为已清）
  • ALV 表格导出：用"导出表格(SAP)"指令或 SAP 原生导出

⚠️ ALV 导出格式不稳定：ALV 表格列顺序可能变化，RPA 抓取需按列名而非列序号定位[15]。

⚠️ 清账需逐凭证执行：F-44 一次清一个客户/供应商，需循环处理。

案例3：资产购置与折旧自动化（FI-AA）

场景：批量创建资产主数据并执行月度折旧运行。

关键 T-Code 与控件

  • AS01：创建资产主数据（资产类别/公司代码/成本中心）
  • AS02：更改资产（补充折旧开始日/使用年限）
  • AFAB：折旧运行（批量计算当月折旧）
  • AS03：显示资产（验证）

⚠️ 资产号自动生成：AS01 保存后系统自动生成资产号，需从状态栏抓取[16]。

⚠️ AFAB 折旧运行报错：资产主数据不完整（缺折旧参数）会导致 AFAB 报错，需先检查日志修复再重跑。

案例4：银行对账单导入与清账（FI-BL）

场景：将银行电子对账单导入 SAP 并自动匹配清账。

关键 T-Code 与控件

  • FF67：手工对账单导入（银行账户/对账单日期/明细行）
  • FEBA：显示电子银行对账单
  • 匹配规则：按金额/凭证号/日期自动匹配

⚠️ MT940 格式解析：银行流水格式各异，需 RPA 预处理为 SAP 可识别格式[17]。

⚠️ 未匹配项需人工判断：自动匹配率约80%，剩余需人工核对。

案例5：成本中心主数据批量维护（CO-CCA）

场景：年初需批量创建/更新数百个成本中心主数据。

关键 T-Code 与控件

  • KS01：创建成本中心（成本中心号/名称/层级/公司代码）
  • KS02：更改成本中心
  • KS03：显示成本中心（验证）

⚠️ 成本中心已存在报错：KS01 遇重复会弹窗，需 RPA 捕获后改用 KS02 更新[18]。

⚠️ 成本中心层级需先建父级：子成本中心的父级必须先创建。

案例6：内部订单批量创建与结算（CO-IO）

场景：批量创建内部订单并月末执行结算。

关键 T-Code 与控件

  • KO01：创建内部订单（订单类型/公司代码/结算规则）
  • KO8G：内部订单批量结算
  • KO02：更改内部订单

⚠️ 结算规则必填：无结算规则的订单无法结算，KO01 需填结算接收方[19]。

⚠️ KO8G 结算需账期开放：结算期间须在 OB52/MMRV 中开放。

案例7：生产订单工单确认与报工（CO-PC）

场景：车间每日需对数百个生产工单进行报工确认（CO11N），录入工时/数量/废品。

关键 T-Code 与控件

  • CO11N：工单确认（工单号/确认数量/工时/废品）
  • CO02：更改生产订单
  • COOIS：生产订单信息系统（查询工单状态）

⚠️ 报工数量超出工单数量：CO11N 报工数量不能超过工单计划数量，否则报错[20]。

⚠️ 工单状态限制：已关闭（TECO）的工单无法报工，需先 CO02 检查状态。

案例8：批量滚算制造件及半成品标准价格（CK11N/CK24）

场景：月初对所有自制半成品和产成品执行标准成本滚算并发布。人工需逐个物料在 CK11N 中执行成本估算（基于 BOM 展开+工艺路线+作业价格计算标准成本），再在 CK24 中批量标记发布。物料数百至上千种，人工耗时数天且极易遗漏，导致当月存货计价和差异分析不准。

关键 T-Code 与控件

  • CK11N：物料标准成本估算（输入物料号/工厂/成本核算变式/估值日期）
  • CK24：标记/发布标准价格（输入工厂/估值日期/物料范围，先测试标记再正式发布）
  • CK13N：成本估算明细查看
  • CKR1：删除成本估算（已发布的需先删除才能重算）
  • MM03：验证物料标准价格已更新（成本视图1当前标准价=将来价格，状态FR）
  • CKMPCD：价格变动凭证（有库存时发布产生FI凭证）
  • CK40N：批量成本估算运行（替代逐个CK11N的批量方案，6步流程）
  • 状态机：KA（估算完成）→ VO（已标记）→ FR（已发布），FR后不可重算

⚠️ 前置数据必须齐备：CK11N 估算前需确保 BOM（CS01/CS03）、工艺路线（CA01/CA03）、作业价格（KP26）均已维护，否则估算报错[21][22]。

⚠️ 估值日期不能晚于当前日期：CK11N 的成本核算起始日必须 ≥ 当前日期，否则系统报错[23]。

⚠️ 已发布不可重算：已到 FR 状态的物料再跑 CK11N 报错，必须先 CKR1 删除评估[23]。

⚠️ 当期已有实际业务无法改价：一旦本月该物料有实际业务发生，无法发布/更改标准单价——月结窗口期非常窄[23]。

⚠️ 价格变动产生FI凭证：有库存时 (新价−旧价)×库存 自动过账，RPA 需预校验库存避免误发布[23]。

⚠️ CK24测试运行先行：标记/发布前必跑 Test Run，RPA 解析日志无 E 类错误后再正式运行[21]。

⚠️ OKKN成本核算变式配置：变式不读取信息记录价格时需在 OKKN 评估变式中配置"来自信息记录的价格"[24]。

⚠️ 批量估算优先用CK40N：单个补跑用CK11N；避免用底层BAPI跑大批量（CK_F_MATERIAL_CALC无return且遇错跳前台弹窗）[25]。

✅ 状态机驱动流程：以 KA→VO→FR 状态码作为流程跳转和异常分支依据，估算失败物料写入异常队列单独补跑。

✅ CKMLCP不可替代：CKMLCP 是月末实际成本核算/物料分类账月结，与期初标准价估算（CK11N/CK40N）是不同环节，不能替代[26]。

踩坑提示

⚠️ 服务端参数重启丢失：RZ11 更改立即生效但系统重启后丢失，需联系 SAP Basis 管理员做永久配置[8]。

⚠️ 元素ID变化：SAP GUI 的控件 ID 会根据屏幕布局变化，录制好的脚本可能失效。用"根据特征"定位方式，结合文本、位置等多个特征；优先用控件路径(ID)而非菜单文字定位[5]。

⚠️ 多语言界面：SAP 支持多语言，菜单路径会因语言不同而位置变化。控件路径(如 ctxtMATNR)是固定的，不受语言影响，建议通过子ID而非菜单文字定位[1]。

⚠️ 权限不足：某些事务码需要特定权限。提前确认 SAP 账号权限，或在流程中捕获权限错误并通知管理员[5]。

⚠️ 图像识别被Windows拦截：Windows 11 需关闭"屏幕截图工具"的后台权限，否则 RPA 截屏识别时会被系统拦截[10]。

⚠️ 建立元素库：把常用的 SAP 界面元素保存到元素库，提高流程稳定性[5]。

⚠️ 批处理模式：一次处理一个 Excel 文件的所有订单，减少登录次数[5]。

SAP 自动化核心路径：先尝试 SAP 脚本录制获取精确控件路径 → 用 win32com.client 直接调用控件(最稳) → 处理好等待和弹窗 → 做好异常日志[1]。

建议从简单场景入手：先从简单的报表导出开始，逐步过渡到复杂的数据录入场景[5]。
