SAP 自动化概述

SAP GUI 自动化的四大难点

SAP GUI 是基于 SAP 专有协议的客户端，和普通 Windows 程序不同，自动化面临四大核心挑战[1]：

难点说明
元素ID不固定SAP GUI的控件ID会根据屏幕布局变化。同样的"物料编号"输入框，不同事务码下ID不一样，今天能用的定位明天可能失效
脚本功能默认关闭SAP默认不允许第三方脚本操控GUI，未开启时影刀识别不到SAP界面元素
系统响应延迟SAP事务处理会有0.5-3秒延迟，查询、过账都会有等待，不加等待就会点击失败
特殊控件无法直接操作SAP的Grid View（ALV报表）、树形控件、导航栏不是标准Windows控件，普通点击无效

此外，SAP GUI 安装后默认并不允许外部脚本控制界面，很多脚本"连不上"的根因在于 SAP GUI 设置里把脚本功能关了[2]。

为什么需要 RPA

OA 和 SAP 几乎是所有企业都会使用的信息管理系统。虽然这些系统给企业信息化带来了便利，但依赖人工操作、效率提升难这一痛点仍困扰大多数企业。RPA 通过模拟人工在计算机上的操作，将规则性强、重复性高的业务实现自动化[3]。

核心价值：非侵入性部署（RPA 能把对现有系统的影响降到最小，与 OA、SAP 无缝连接，无需开发接口、不用懂 ABAP）；7×24 小时精准执行；流程标准化。有客户通过影刀 RPA 将月度财务关账流程从 3 天缩短到 4 小时[4]。

前提准备：SAP GUI Scripting 启用

SAP GUI Scripting 的启用必须同时配置服务端和客户端，否则客户端拒绝对 UI 的访问。如果不能在服务端打开，就只能用图像识别方式[6]。

步骤一：服务端参数配置（事务码 RZ11）

  1. 启动 saplogon.exe，用账号密码登录 SAP 进入主页。
  2. 在命令框输入事务码 RZ11，按回车。
  3. 参数名称输入 sapgui/user_scripting，点击"显示"。
  4. 点击"更改值"，新值设置为 TRUE，保存更改[7]。
  5. 重复，将以下参数值改为 FALSE：
    • sapgui/user_scripting_disable_recording → FALSE
    • sapgui/user_scripting_force_notification → FALSE
    • sapgui/user_scripting_per_user → FALSE
    • sapgui/user_scripting_set_readonly → FALSE
  6. 注销后重新登录 SAP。

重要：事务 RZ11 中对参数的所有更改均立即生效，但在系统重新启动时丢失。要使更改永久生效，需联系 SAP 系统管理员。若重启 SAP Service 之后要重新设置服务端脚本设置[7][8]。

步骤二：客户端启用脚本

  1. 登录 SAP 后，点击菜单栏 "定制本地布局"（快捷键 Alt + F12），选择 "选项"[8]。
  2. 在弹出窗口点击 "辅助功能与脚本" → "脚本"。
  3. 勾选 "启用脚本(Enable Scripting)"。
  4. 取消勾选以下两项（避免运行时弹通知干扰）：
    • "在脚本附加到SAP GUI时发出通知"
    • "在脚本打开连接时发出通知"

步骤三：启用对话框模式（日期选择/帮助必用）

  1. 点击菜单 "帮助(H)" → "设置(N)"。
  2. 在"用户DDIC的人员设置"对话框，选 "F1帮助" 页签，选中 "以对话框模式"。
  3. 选 "F4帮助" 页签，在"显示"区域选中 "控制(amodal)"[8]。

补充：录制/回放时需保证产品与 SAP 客户端以同样权限执行；RDP/Citrix 环境需以管理员权限启动 SAP；配置完成后需重启 SAP 才可生效；SAP GUI 7.4+ 客户端支持自动化。

影刀侧准备

  1. 打开影刀RPA 设计器，新建自动化应用。
  2. 左侧指令面板搜索"SAP"，找到 "登录SAP" 核心指令[4][9]。
  3. 配置连接参数：连接名自定义（如 MySAP_PRD）；SAP窗口标题手动打开 SAP 登录窗口复制完整标题粘贴。
  4. 安装时勾选"影刀浏览器"和"图像识别组件"（图像识别兜底所需）[10]。
  5. Windows 11 需关闭"屏幕截图工具"后台权限，否则影刀截屏识别时会被系统拦截[10]。

元素拾取策略

影刀在桌面场景下的元素定位"四合一"为：UIA元素、MSAA元素、坐标、图像识别。能捕获到控件名就用元素捕获，捕获不到再切图像[10]。针对 SAP，有三种核心捕获方法：

方法一：标准桌面捕获（SAP GUI Scripting 方式）

启动影刀元素捕获，悬停在 SAP 界面输入框上，大多数标准 SAP 输入框可正常捕获：

  • 类型通常是 GuiTextField 或 GuiCTextField
  • 属性里有 Name，就是输入框字段名（如 MATNR 表示物料号）

捕获到元素后，"输入文本"指令可直接用。这是首选方案，前提是已开启 SAP GUI Scripting[1]。

方法二：图像识别定位（处理特殊控件）

当标准捕获失败时，用图像识别作为备用定位，再配合"坐标偏移"：先用文字识别找到标签文字，再计算标签右侧固定偏移位置找到输入框。

方法三：SAP GUI 脚本录制（最稳定）

SAP 内置脚本录制功能，录制完成后得到 VBScript，里面有每个操作的精确控件路径，可在影刀 Python 中通过 COM 接口调用。这是最稳定的 SAP 操作方式，控件路径不受屏幕分辨率影响。[1]

拾取失败的应对

无法拾取 SAP 元素时，根因通常是 SAP GUI Scripting 未开启/权限隔离[11]：

  • 检查服务端 sapgui/user_scripting 是否为 TRUE
  • 检查客户端是否勾选"启用脚本"
  • 如果选项是灰色的，说明被 SAP 管理员禁用了，需要找 IT 开通

常用操作详解

SAP 登录自动化

影刀操作步骤[5]：

  1. 新建流程「SAP自动化」。
  2. 添加 【打开应用程序】 指令 → 路径：SAP GUI 快捷方式。
  3. 添加 【窗口激活】 指令 → 窗口标题：SAP。
  4. 添加 【点击】 指令 → 定位值：连接按钮。
  5. 添加 【填写】 指令 → 定位值：用户名输入框 → 填入：变量 sap_username。
  6. 添加 【填写】 指令 → 定位值：密码输入框 → 填入：变量 sap_password。
  7. 添加 【点击】 指令 → 定位值：登录按钮。

另一种方式是通过 Python COM 接口直接连接（无需手动登录，已有 SAP 会话时）：

SapGuiAuto = win32com.client.GetObject("SAPGUI")
application = SapGuiAuto.GetScriptingEngine
connection = application.Children(0)
session = connection.Children(0)

来源：影刀RPA SAP系统自动化入门[1]。

执行事务码（T-Code）

影刀可视化指令方式[5]：

  1. 添加 【点击】 指令 → 定位值：命令框（okcd）。
  2. 添加 【填写】 指令 → 定位值：命令框 → 填入：VA01（创建销售订单）。
  3. 添加 【键盘输入】 指令 → 按键：Enter。

Python COM 方式（最稳定）：

session.findById("wnd[0]/tbar[0]/okcd").text = "/nME21N"
session.findById("wnd[0]").sendVKey(0)  # 发送回车

用 /n 前缀表示跳转到新事务码（中断当前事务），不加 /n 则在当前事务内执行[1][12]。T-Code 的价值：SAP 界面跳转的捷径，不需点击科目，直接在搜索框输入 T-Code 按回车跳转，比图像判断+点击方便且稳定。

表格 / ALV 操作

ALV Grid 控件路径格式为 tbl表名/字段名[列索引,行索引]，逐行处理时循环行索引即可[1]：

# 表格中控件路径，[列,行]定位单元格
session.findById("wnd[0]/.../tblSAPLMEPOTC_1111/ctxtMEPO1111-MATNR[1,0]").text = material

修改 SAP 表格内容：影刀社区指出目前有"读取SAP表格"指令，但没有直接的"修改SAP表格"标准指令。解决方案是 SAP 自动化配置好后，用桌面软件自动化指令（如"设置元素值(win)"指令）来操作[13]。

实战案例：采购订单 ME21N 批量创建

场景：每天有 100 条采购需求，要在 SAP ME21N 事务码中批量创建采购订单[9][1]。

关键操作要点

  1. 打开事务码：session.findById("wnd[0]/tbar[0]/okcd").text = "/nME21N"，发送回车。
  2. 填写供应商：控件路径 wnd[0]/usr/subSUB0:SAPMM06E:0101/.../ctxtEKKO-LIFNR。
  3. 填写行项目：ALV 表格控件路径含 [列索引,行索引]，如 ctxtMEPO1111-MATNR[1,0] 为第1列第0行的物料号。
  4. 保存：点击 wnd[0]/tbar[0]/btn[11]（保存按钮）。
  5. 获取订单号：从状态栏 wnd[0]/sbar 提取文本，用正则匹配订单号（如"采购订单 4500001234 已保存"中提取数字）。
  6. 错误处理：try-except 捕获异常，失败原因写回 Excel。

销售订单批量创建（VA01）

销售订单创建流程类似，事务码为 VA01[5]：

  1. 执行事务码 VA01。
  2. 填写订单类型 OR（标准订单）→ 回车。
  3. 填写销售组织 1000、分销渠道 10、产品组 00 → 回车。
  4. 用【Excel读取】指令读取订单数据 → 【循环】遍历。
  5. 循环内：填写物料号、数量、单价，Tab键跳转字段，点击添加新行。
  6. 点击保存按钮 → 等待2秒 → 获取状态栏订单号 → 写入日志。

财务场景实战：CO/FI 模块 7 大案例

以下案例覆盖 SAP 财务会计（FI：总账/应收/应付/资产/银行）与管理会计（CO：成本中心/内部订单/生产订单）两大模块的成熟自动化场景，每个含步骤序列流程图、关键 T-Code 与控件路径、踩坑提示。所有案例共用前置配置：服务端 RZ11 开启 sapgui/user_scripting=TRUE，客户端启用脚本并设为模态对话框，屏幕缩放必须 100%[14]。

影刀SAP专属指令：获取窗口对象(sap)、点击工具栏按钮(sap)（按钮名如"过账(Pst)/保存(Save)/执行(Exec)"）、选中树节点(sap)（路径如"SAP菜单/会计核算/控制"）、导出表格(SAP)（在SAPGUIGridView元素右键→电子表格→保存）[14][15][16][17]。

案例1：SAP 凭证批量录入与过账（FB01/FB50）FI-GL

场景：月度结账需将几十至上百张会计凭证（费用计提、费用分摊、调整凭证）逐张录入 SAP 并过账。人工单张耗时2-5分钟，月末集中处理极易疲劳出错[18][19]。

关键 T-Code 与控件

  • FB01：输入总账凭证（标准模式），支持多行凭证；FB50：Enjoy界面，仅总账科目；F-02：快速模式；FB03：显示凭证（回写校验用）[19][20]。
  • 抬头字段：凭证日期(BlngDate)、参照(Reference)、凭证类型(DocType)、公司代码(CompanyCode)、过账日期(PstngDate)、货币(Currency)。
  • 行项目：科目(G/L Account)、D/C(借/贷)、金额(Amount)、成本中心(Cost Center)、利润中心(Profit Center)、文本(Text)。
  • 过账按钮：工具栏按钮名"过账(Pst)"[16]。

⚠️ posting key 概念：FB50 仅总账科目；含客户/供应商须 FB01 配 posting key（01=借客户、50=贷总账），否则无法过账[20]。

⚠️ 借贷不平衡直接报错阻断：影刀先用计算指令对 Excel 每张凭证求和校验借贷相等，不平衡的行标红跳过。

⚠️ 凭证号提取：过账成功后状态栏显示"凭证 ×××× 已过账"，用"获取SAP状态栏文本"提取，注意多语言文案差异。

⚠️ 会计期间未开：OB52 未开放当月期间会过账失败，流程前确认期间已开或加前置检查。

⚠️ Scripting Tracker 录制法：社区推荐先用 Scripting Tracker 录制一遍 SAP 操作生成 Python 代码，复制到影刀调整参数[18]。

案例2：SAP 应收/应付对账自动化（FBL1N/FBL5N）FI-AP/AR

场景：定期导出 AP/AR 明细，与银行流水或内部系统对账。汽车零部件企业案例：对账时间从4小时缩短至15分钟，准确率100%[21][22]。

关键 T-Code 与控件

  • FBL1N：供应商行项目显示；FBL5N：客户行项目显示；FK10N/FD10N：供应商/客户余额概览[23]。
  • ALV 网格控件名形如 SAPGUIGridViewCtrl1，用影刀【导出表格(SAP)】指令：右键→电子表格→指定 save_path[17]。
  • 筛选界面：供应商/客户范围(Account)、公司代码、未清项/已清项/全部、过账日期。

⚠️ ALV导出弹窗：导出时 SAP 可能弹出格式/路径选择窗口，需提前捕获弹窗元素自动确认，否则卡住[24]。

⚠️ 大数据量分页：上千行时 SAP 默认分批加载，导出前需确保完整加载（设显示行数上限或循环翻页）。

⚠️ 结算单号格式不一致：OA与SAP单号可能有前导零/分隔符差异，匹配前需在影刀做格式标准化[25]。

⚠️ 未清/已清项混淆：对账须明确筛"未清项"还是"已清项"，勾错导致余额对不上。

  • AS01：创建资产（资产分类+公司代码→General标签填描述，Time Dependent标签填成本中心）；AS02修改；AS03显示[26]。

案例4：SAP 银行对账单导入与清账（FF67）FI-BL

场景：将银行流水导入 SAP 并自动清账。某集团每月8200+条流水对账，影刀让8个财务人员高效处理[22][28]。

flowchart TD A[影刀登录网银下载流水Excel] --> B[读取银行流水] B --> C[登录SAP执行FF67] C --> D[填抬头:公司代码/开户行/账户ID/对账单号/日期/期初期末余额] D --> E[循环每条流水] E --> F[输入业务交易码+金额+value date+摘要] F --> G{是否还有流水} G -->|是| E G -->|否| H[保存对账单触发自动清账] H --> I[处理未清项:F.13自动清账/F-44手动] I --> J[导出清账报告:余额调节表]

图：银行对账单导入与清账流程

关键 T-Code 与控件

  • FF67：手工银行对账单录入。抬头：公司代码、开户行(HouseBank)、账户ID、对账单编号、对账单日期、期初/期末余额、过账日期。
  • 行项目：业务交易码(EZK借/EZI贷)、金额、估价日(ValueDate)、分配、文本。
  • F.13：自动清账；F-44：供应商清账；F-32：客户清账[23]。

⚠️ 业务交易码映射：流水业务类型须映射为 SAP 业务码（EZK=客户收款借方/EZI=供应商付款贷方），映射表错则清账方向错。

⚠️ 期初期末余额不平：FF67 要求"期初+借方合计-贷方合计=期末"，影刀录入前用计算指令校验平衡。

⚠️ 对账单编号唯一性：同开户行+账户ID的对账单编号不可重复，Excel 维护递增编号列。

⚠️ 大额流水导入慢：上百行逐条录 FF67 慢，可考虑电子银行对账单(EBS)文件导入替代[28]。

案例5：SAP 成本中心主数据批量维护（KS01/KS02）CO-CCA

场景：年度初批量创建/修改成本中心（新建车间、调整组织架构、变更负责人）[23][15]。

flowchart TD A[读取成本中心Excel] --> B[登录SAP] B --> C{新建或修改} C -->|新建| D1[执行KS01] C -->|修改| D2[执行KS02] D1 --> E[输入成本中心编号+控制范围] D2 --> E E --> F[回车进主数据] F --> G[基本标签:描述/负责人/类型] G --> H[层次标签:标准层次位置] H --> I[公司代码标签:关联公司代码] I --> J[输入有效期] J --> K[保存] K --> L{是否还有记录} L -->|是| D1 L -->|否| M[批量激活/解锁] M --> N[导出KS13清单校验]

图：成本中心主数据批量维护流程

关键 T-Code 与控件

  • KS01：创建（成本中心编号+控制范围→基本标签填描述/负责人/类型/层次）；KS02修改；KS03显示；KS13清单导出校验[23]。
  • KSH1：创建成本中心组；KSV1：创建实际分配循环。
  • 树节点操作可用影刀【选中树节点(sap)】指令，路径如"SAP菜单/会计核算/控制"[15]。

⚠️ 标准层次必填：每个成本中心须挂在标准层次节点下，层次路径错会导致孤立，报表查不到。

⚠️ 控制范围一致性：批量导入的多个成本中心须属同一控制范围，跨范围需分批处理。

⚠️ 有效期与锁定：有效期设在未来则当前无法记账；已过账的不能删除只能锁定，KS02 解锁需在有效期内。

⚠️ 公司代码关联：成本中心须关联公司代码才能记成本凭证，漏关联则 KB1N 记账报错。

案例6：SAP 内部订单批量创建与结算（KO01/KO8G）CO-IO

场景：项目型企业（研发/营销/技改）的内部订单创建与月末结算。月末用 KO8G 批量结算到目标成本中心/在建工程[29][30]。

flowchart TD A[读取订单Excel] --> B[登录SAP] B --> C[循环每条订单] C --> D[执行KO01] D --> E[选择订单类型+公司代码] E --> F[回车进主数据] F --> G[基本标签:描述/负责人] G --> H[结算规则标签:定义结算分配] H --> I[预算标签:维护预算KO22] I --> J[保存提取订单号写回Excel] J --> K{是否还有订单} K -->|是| D K -->|否| L[月末执行KO8G批量结算] L --> M[输入结算范围+期间] M --> N[测试运行→检查日志] N --> O[正式运行→生成结算凭证] O --> P[导出结算报告KOB1/KO03]

图：内部订单批量创建与结算流程

关键 T-Code 与控件

  • KO01：新建（订单类型：费用型/收入型）；KO02：修改（维护结算规则）；KO03：显示；KOK3：集中显示[23]。
  • KO88：单个结算；KO8G：批量结算（月末用）；KOB1：行项目显示；KO22：维护预算[29]。
  • 结算规则控件为表格控件（行：结算类别/接收者/百分比/源）。

⚠️ 结算规则必须维护：KO01 建单后未配结算规则则 KO8G 跳过该订单，建议建单即配规则。

⚠️ KO88 vs KO8G：KO88 单个、KO8G 批量；首次用"全量"，后续月份用"Δ(差异)"，选错会重复结算。

⚠️ 测试运行先行：KO8G 必须先"测试运行(Test Run)"检查无报错再正式运行。

⚠️ 订单状态控制：订单须为"REL(已释放)"状态才能结算，建单后需 KO02 释放。

案例7：SAP 生产订单工单确认与报工（CO11N/CO02）CO-PC

场景：制造企业每天对生产工单报工确认（完成数量、耗用工时），漏报/错报影响成本核算与在制品(WIP)[31][32]。

flowchart TD A[读取报工数据Excel] --> B[登录SAP] B --> C[循环每条报工] C --> D[执行CO11N] D --> E[输入生产订单号回车] E --> F[选择工序号] F --> G[选择确认类型:部分/最终/自动最终] G --> H[输入良品产量] H --> I[输入废品数量+确认工时] I --> J[填确认人员/日期] J --> K[保存提取确认号] K --> L[写回Excel] L --> M{是否还有报工} M -->|是| D M -->|否| N[处理差异:CO02修改/CO13取消] N --> O[导出报工报表COOIS/KOB1]

图：生产订单工单确认与报工流程

关键 T-Code 与控件

  • CO11N：报工（订单号+回车→工序号→确认类型→产量/废品/工时）；CO11旧界面；CO15：按订单整体确认[31]。
  • CO02：修改订单；CO13：取消报工确认；COOIS：生产订单信息系统（导出报表）；KOB1：订单成本[32]。
  • CO88：生产订单结算；KKAO：计算WIP；KKS1：计算差异。

⚠️ 工序顺序报工：多工序必须按前后顺序依次报工，不得从后往前，否则后工序报工被拦截。影刀循环前按工序号升序排序 Excel。

⚠️ 确认类型选择：部分确认(Partial)可多次累加；最终确认(Final)后不可再报；批量默认用部分确认，完工才用最终确认[31]。

⚠️ 良品+废品≤订单数量：超量 SAP 报错，Excel 预处理校验。

⚠️ 报工自动收货：CO11N 可触发自动入库，若后台配了自动收货则报工后库存自动增加，影刀无需另做 MIGO[32]。

⚠️ 取消报工用 CO13：报工错误须 CO13 取消原确认再重报，不能直接 CO02 改数量。

踩坑提示

⚠️ 服务端参数重启丢失：RZ11 更改立即生效但系统重启后丢失，需联系 SAP Basis 管理员做永久配置[8]。

⚠️ 元素ID变化：SAP GUI 的控件 ID 会根据屏幕布局变化，录制好的脚本可能失效。用"根据特征"定位方式，结合文本、位置等多个特征；优先用控件路径(ID)而非菜单文字定位[5]。

⚠️ 多语言界面：SAP 支持多语言，菜单路径会因语言不同而位置变化。控件路径(如 ctxtMATNR)是固定的，不受语言影响，建议通过子ID而非菜单文字定位[1]。

⚠️ 权限不足：某些事务码需要特定权限。提前确认 SAP 账号权限，或在流程中捕获权限错误并通知管理员[5]。

⚠️ 图像识别被Windows拦截：Windows 11 需关闭"屏幕截图工具"的后台权限，否则影刀截屏识别时会被系统拦截[10]。

⚠️ 建立元素库：把常用的 SAP 界面元素保存到元素库，提高流程稳定性[5]。

⚠️ 批处理模式：一次处理一个 Excel 文件的所有订单，减少登录次数[5]。

SAP 自动化核心路径：先尝试 SAP 脚本录制获取精确控件路径 → 用 win32com.client 直接调用控件(最稳) → 处理好等待和弹窗 → 做好异常日志[1]。

建议从简单场景入手：先从简单的报表导出开始，逐步过渡到复杂的数据录入场景[5]。
